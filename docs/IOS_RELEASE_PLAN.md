# iOS 上架評估（App Store）

評估日期：2026-07。結論先講：**可行，而且放置塔防是 App Store 上成熟且低審核風險的類型**（參考作品《The Tower》本身就在 App Store 上）。但「要上 iOS」這個決定會直接影響技術選型，最好在 M0 原型階段就定下來。

---

## 1. 對技術選型的影響（最重要的決定）

| 方案 | iOS 上架可行性 | 說明 |
|------|----------------|------|
| **Godot 4 原生輸出** ✅ 建議 | 高 | 官方支援 iOS 匯出（經 Xcode 打包簽章），已有多款 Godot 遊戲上架 App Store（如 Unnamed Space Idle）。IAP/廣告有社群外掛 |
| Unity | 高 | 最成熟的手遊管線，但引擎較重、有收費政策考量 |
| **Web 遊戲用 WebView 包殼（Capacitor/Cordova）** ⚠️ 不建議 | 有拒審風險 | Apple 審核準則 4.2（Minimum Functionality）對「網頁包殼 App」很嚴格，HTML5 遊戲包殼被拒的案例多；效能（幾百敵人同屏）也吃虧 |

**建議路線**：維持原規劃 —— 用 TypeScript + PixiJS 做 M0 網頁原型**只為驗證玩法數值**，玩法確認後 **M1 起改用 Godot 4 重建**，之後 web/iOS/Android 三平台都從 Godot 輸出。如果你已經確定目標就是 iOS 上架，也可以跳過 web 原型直接從 Godot 開始，省一次移植。

---

## 2. 硬性需求與成本

| 項目 | 內容 | 成本 |
|------|------|------|
| Apple Developer Program | 個人帳號即可，須年繳 | **US$99/年** |
| Mac + Xcode | iOS 打包簽章必須經過 Xcode；**2026/4/28 起強制使用 Xcode 26 / iOS 26 SDK** 編譯 | 已有 Mac 則 $0；沒有可用雲端 Mac（GitHub Actions macOS runner 等） |
| App Store Connect | 免費，上架後台（截圖、描述、定價、審核送件） | $0 |
| 隱私權政策網頁 | 必填 Privacy Policy URL，可放 GitHub Pages | $0 |
| 美術資產 | App Icon（1024px）、各尺寸截圖（6.9"/6.5" iPhone；若支援 iPad 加 13"）、選配預覽影片 | 自製 $0～外包數千元 |

**總結：最低現金成本就是每年 US$99 + 一台能跑 Xcode 的 Mac。**

---

## 3. 合規檢查清單（2026 年版）

送審前必須完成，漏掉任何一項都是常見拒審原因：

- [ ] **隱私標示（Privacy Nutrition Label）**：在 App Store Connect 如實申報收集哪些資料。純單機放置遊戲若不接廣告/分析，可以幾乎全空 —— 這是巨大優勢。
- [ ] **Privacy Manifest**：2024 起強制。使用特定 API（如 UserDefaults）與第三方 SDK（廣告、分析）都要在 manifest 中申報用途，是 2025–2026 最常見拒審原因之一。
- [ ] **新版年齡分級問卷**：2026/1/31 起採用更細的分級題目（含 AI 聊天、UGC 頻率等）。本遊戲為幾何風格暴力，預期分級 9+ 或 12+，無障礙。
- [ ] **IAP 規範**：所有虛擬貨幣（Gems）只能走 Apple IAP，抽成 30%；**申請 Small Business Program 後年營收 US$100 萬以下抽 15%** —— 獨立開發者務必申請。
- [ ] **轉蛋機率公示（Guideline 3.1.1）**：若做卡片抽獎/隨機寶箱，必須公布各稀有度機率。若 Meta 系統設計成「定價直購 + 明確進度」可完全避開。
- [ ] **廣告與 ATT**：接 AdMob/AppLovin 等廣告 SDK 就要處理 App Tracking Transparency 彈窗與 SDK 的 privacy manifest。**建議首版不接廣告、純 IAP 或完全免費**，把合規面積縮到最小，之後再加。
- [ ] **社交功能申報**：2026/9 起送審須申報是否含社交功能。本遊戲若無聊天/好友系統，直接申報「無」。

## 4. 審核風險評估

| 風險 | 等級 | 對策 |
|------|------|------|
| 4.2 Minimum Functionality（太簡陋/像網頁殼） | 中 → 低 | 用 Godot 原生輸出；確保有離線收益、觸覺回饋、儲存等「像原生 App」的完整度再送審 |
| 隱私申報不實 | 低 | 首版不接第三方 SDK 就幾乎無此風險 |
| 遊戲類型本身 | 極低 | 放置塔防無敏感內容，同類上架案例極多 |
| 崩潰/明顯 Bug | 低 | 送審前跑滿 TestFlight 測試（見下） |

一般審核時間目前約 24–48 小時；首次送審預留一週緩衝比較保險。

---

## 5. 營利模式建議（比照參考作品）

放置遊戲在 iOS 的標準組合，按導入順序：

1. **免費下載 + 觀看廣告換 Gems（Rewarded Ads）**：放置遊戲主收入，玩家自願觀看、體驗傷害最小。但因合規成本（ATT、SDK manifest），建議 v1.1 再加。
2. **Gems IAP 直購**：小額檔位（US$0.99–$9.99）+ 一次性「新手包」。
3. **去廣告/月卡**：長線留存收入。
4. 避免：強制插頁廣告（傷留存、傷評分）、首版就做轉蛋（多一項機率公示合規）。

## 6. 上架流程與時程

```
開發完成（路線圖 M2 之後）
  → 註冊 Apple Developer Program（審核 1~2 天）
  → App Store Connect 建立 App、填分級/隱私/定價
  → TestFlight 內部測試（自己 + 朋友，最多 100 內部/10,000 外部測試員）
  → 修 Bug、跑滿至少 1~2 週真機測試（含舊機型效能）
  → 送審（預留 1 週）→ 上架
```

**對開發路線圖的影響**：原規劃 M4「上線準備」展開為 —— 隱私政策頁面、App Store 資產（icon/截圖/描述 zh-TW + en 雙語）、TestFlight beta、合規清單逐項打勾。建議 M2 完成時就先註冊開發者帳號並把 TestFlight 跑起來，讓真機回饋提早進入迭代。

---

## 7. 結論

- **可行性：高。** 類型成熟、無敏感內容、單機架構讓隱私合規幾乎為零負擔。
- **關鍵決定：現在就確認要上 iOS，然後把主引擎定為 Godot 4**，避免 web 原型做太深導致二次移植成本。
- **最小成本路徑**：Godot 4 + 無廣告無 IAP 的免費版先上架（合規面積最小、最快過審）→ 有玩家基數後 v1.x 再逐步加 IAP 與 Rewarded Ads。
